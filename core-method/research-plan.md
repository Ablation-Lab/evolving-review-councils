1. Find the optimum council size, and the most efficient setup overall.
2. Produce a default recipe built around a median token budget per app build, with a hard agent cap.
3. Define the prerequisites for raising that cap.
4. Check that the recipe holds across different kinds of apps.

## 7. Analysis

- **The keep rule:** a generation advances only if a 90% confidence interval for its score minus its parent's, computed on the same seeds, lies above zero ([plan L21](https://github.com/Ablation-Lab/evolving-review-councils/blob/87eb410/core-method/experiment-plan.md?plain=1#L21)). Decision 6, adopted 2 Nov, specifies a paired bootstrap or McNemar-based interval on recall, with an optional precision guard ([decision 6 L248](https://github.com/Ablation-Lab/evolving-review-councils/blob/87eb410/research/decision-6-seeds-and-stopping.md?plain=1#L248), [sheet L73](https://github.com/Ablation-Lab/evolving-review-councils/blob/87eb410/research/decisions-seeded-bugs-and-judge.md?plain=1#L73)). > - **What the appeal can do:** it doesn't re-judge every finding. It sees only the judge's dismissals (each NOT REAL finding, with the judge's reasons) and a severity block, and marks each dismissal WRONGLY DISMISSED, FAIRLY DISMISSED or UNSURE. That's from Council Dial's version 3 appeal brief and the notebook's "What each council seat is told". The judge's brief doesn't mention the appeal.
> - **What that changes:** within a run, the appeal can only add catches (a wrongly dismissed seed restored) and extras (a fair dismissal restored), never remove either. So "the appeal recovers no more real bugs than the judge alone" is false as soon as one seed is restored, and testing it says little. Its largest possible gain is the judge's wrongful-dismissal rate, likely a few points, far below what a comparison between separate runs can detect: about 10 to 12 points at 105 seeds × 3 repeats, one-sided, by `pairwise.py`. > - **Proposed design:** within-run.
